本文档与仓库内 说明.md 内容一致，HTML 版便于在线浏览与分享。 仓库地址：https://github.com/chenzhuanxin/futures-weighted-panel

1. 快速开始

方式 A：单文件 EXE（推荐给最终用户）

  1. 从 Releases 下载 futures-weighted-panel-v1.0.0-win64.exe（约 94 MB）。
  2. 双击运行。单文件 EXE 需先自解压，约 5~10 秒后才弹出黑色控制台窗口，属正常现象。
  3. 启动后自动打开浏览器，默认地址 http://127.0.0.1:8689； 端口被占用会自动改用 8690、8691…，以控制台打印的地址为准。
  4. 首次启动需 20~60 秒预热（拉取全部品种历史日K），预热完刷新即可。
  5. 关闭：直接关掉控制台窗口，或窗口内按 Ctrl+C。
✅ EXE 默认数据源为曲合网（免账号、免密钥，82 个品种有行情，日K 约 3.5 年）—— 双击就有数据。

方式 B：源码运行

下载 源码包 ZIP 解压，然后：

# Windows：直接双击
启动看板.bat

# 或命令行
python 服务端.py                 # 默认 8689 端口，自动打开浏览器
python 服务端.py --port 8888     # 指定端口
python 服务端.py --no-browser    # 不自动开浏览器
⚠️ 源码运行只需 Python 3.9+ 标准库；仅当使用天勤数据源时才需要 pip install tqsdk。

5. 阈值基准（上阈 / 下阈）

一键设阈 = 所选周期 K 线、最近 N 根的动态均值，其中最后一根用当前实时价替代，因此每个 tick 都在变。

位置操作含义
左栏「历史高于均值」一键设下阈价格从上方跌破该均值 → 触发下阈预警
右栏「历史低于均值」一键设上阈价格从下方升破该均值 → 触发上阈预警
  • 可选周期：5 分 / 15 分 / 30 分 / 日K；可选均线参数：MA5 / 8 / 10 / 20 / 30 / 50
  • 偏离度 > 门槛（默认 70%）按钮才可点，与参照网页逻辑完全一致（pct > 70）
  • 实测：15分K·MA20 → 110425.8；5分K·MA8 → 110480.125；日K·MA5 → 109933.6

6. 偏离度百分比

卡片结构（与参照网页一致）：

[进度条  flex:1]  [92.05%]
 bar-container     percent-label

计算口径以「历史均价 M」为 0 基准，高低两侧各自归一化到 0~100：

侧条件公式满格含义
高侧现价 ≥ M(现价 − M) ÷ (H − M) × 100%触及历史最高 H = 100%
低侧现价 < M(现价 − M) ÷ (L − M) × 100%触及历史最低 L = 100%
  • 两侧数值都表示「离开均价、走完该侧全程的比例」，越大越极端；两栏均按降序排列
  • 其中 H = max(high)、L = min(low)、M = mean(close)，均基于该数据源全部可获取的历史日K
  • 价格突破历史极值时会 > 100%（数值不截断，仅进度条打满 min(100, pct)）
  • 偏离度 > 门槛（默认 70%）→ 右侧百分比加粗高亮 + 解锁「一键设阈」
  • 百分比文字粗体 17px、最小宽度 74px 右对齐，随 /api/tick 实时就地重算（不重绘 DOM）
✅ 口径已与参照网页逐条比对：抓取其实时渲染的 87 条数据反算，87/87 完全吻合。
旧版公式（(现价 − L) ÷ (H − L) 的全局位置）已废弃 —— 与参照网页对照，平均偏差达 31 个百分点。 如需全局位置，接口仍返回 position 字段备用。

7. 预警与防轰炸守护

  • 触发条件：实时价上穿上阈 或 下穿下阈
  • 表现：卡片红色高亮 + 提示音 + 邮件（卡片式 HTML，含阈值基准说明）

7.1 为什么需要守护

早期版本是「每轮刷新只要价格在阈值外就发信」，配合默认 120 秒冷却，会产生三类骚扰：

场景旧行为后果
价格突破后长期停在阈值外每 120 秒重复发一封一天最多 720 封
收盘后 / 周末 / 假期收盘价仍在阈值外，照发不误整夜 + 整个周末连续轰炸
多阈值 + 行情普涨/普跌几十个品种各自计时邮件互相叠加

7.2 现在的五层防护

层机制作用
① 边沿触发只有「从阈内穿到阈外」的那一刻才算一次事件；持续停在阈值外不重发一次突破只发一封
② 滞回复位必须回落超过「上阈 ×(1−幅度)」才复位（默认 0.3%），之后再次突破才算新事件滤掉阈值边缘的来回抖动
③ 交易时段门禁闭市期间完全不发信；且闭市期间不置位触发态，开盘首轮若仍在阈值外会补发一封解决整夜 / 周末轰炸
④ 同品种冷却同品种同方向默认 600 秒内最多一封兜底限频
⑤ 全局配额每小时 ≤ 6 封、每天 ≤ 30 封；超出转排队等待，不丢弃上限兜底

另有 ⑥ 启动基线：重启服务端时，首轮只登记「当前谁在阈值外」，默认不补发，避免「一开就炸」。

7.3 交易时段怎么判断（双源通用、零维护）

优先级从高到低，任一条成立即视为「交易中」：

  1. 交易所状态：曲合返回的 status == 100
  2. 行情数据新鲜度（最可靠）：距最后一笔行情 ≤ 300 秒（可配）—— 行情时间戳天然就是最新交易时刻，闭市即冻结， 因此自动适配：同一交易所内不同品种的夜盘差异（沪铜到 01:00 / 螺纹钢到 23:00）、夜盘规则历次调整、周末与法定节假日
  3. 交易所时段表：仅在前两条都取不到时兜底
📌 实测（2026-10-13 00:00 周一）：沪铜 / 沪银 / 原油 → 开市（夜盘进行中）；螺纹钢 / 铁矿石 / 纯碱 → 闭市（夜盘 23:00 已结束）；碳酸锂 / 多晶硅 / 沪深300 → 闭市（无夜盘）。

7.4 面板上怎么看

  • 顶栏 邮件守护 状态位：显示「仅交易时段 / 全天」、今日已发数、排队数
  • 卡片标签：⚠ 已触发；闭市且已设阈时追加 🌙 休市·静默（悬停看具体原因）
  • ⚙️ 设置 → 预警 · 防轰炸守护 底部有实时统计：闭市静默 / 冷却抑制 / 配额抑制 / 队列丢弃次数， 以及「最近为什么没发信」和「最近发信记录」
✅ 实测对比：沪铜（开市）上阈 110000、现价 110429 → 发出 1 封；螺纹钢（闭市）上阈 3000、现价 3083 → 静默不发。 服务端重启后沪铜持续停在阈值外 10 分钟，一封都没发（旧版会发 5 封）。

11. 常见问题

现象原因与解决
浏览器没自动打开手动访问控制台里打印的地址（http://127.0.0.1:8689）
面板一直显示「预热中」天勤源首次连接较慢（30~60 秒），再等一会儿并刷新
天勤提示「tqsdk 不可用」源码运行需 pip install tqsdk；或设置面板里没填账号。只想要数据就切回「曲合网」
曲合某品种无数据该品种为已停止挂牌的「僵尸品种」（零成交零持仓），曲合侧无行情 —— 详见 数据源说明 · 覆盖差异

杀毒软件报毒PyInstaller 单文件 EXE 的常见误报，加入信任即可（源码在同仓库，可自行执行 打包exe.py 核对重建）
EXE 双击后要等很久单文件 EXE 需先自解压，约 5~10 秒出现控制台窗口属正常
端口 8689 被占用自动避让到 8690、8691…，以控制台打印的地址为准
配置放在哪EXE 版在 EXE 同级的 缓存\；源码版在项目 缓存\。EXE 拷到哪配置就跟到哪

12. 重新打包 EXE

C:/Python314/python.exe 打包exe.py      :: 产物 → 发布\加权合约监控面板.exe（约 94 MB）

用 PyInstaller 6.22.3 + Python 3.14 打包，--onefile --console，内置 tqsdk / pandas / numpy / scipy 全量依赖。

关键处理做法
动态导入的中文模块服务端.py 用 importlib.import_module("品种表")，静态分析扫不到 → 必须 --hidden-import 品种表 数据源 邮件预警 天勤行情 曲合行情
只读资源 vs 可写数据看板.html 走 --add-data 打进 EXE（运行时在 sys._MEIPASS）； 配置与缓存改由 _data_dir() 决定 = EXE 所在目录
--add-data 必须绝对路径同时用了 --specpath build 时，相对路径会以 spec 目录为基准 → Unable to find 看板.html
不能排除 pydoc / scipy实测 import tqsdk 会连带导入二者；排除后 from tqsdk import TqApi 抛异常并被误报成「未安装 tqsdk」
账号不进 EXE缓存/ 不打进包，EXE 本体零敏感信息，可安全分发
✅ 打包后实测：曲合源 82 品种正常；天勤源登录成功、174 个合约订阅、87 品种数据齐全。
