1. 两源总览

本项目同时接入 曲合网（金投网） 与 天勤 TqSdk 两个数据源，两者提供的都是 持仓量加权的「加权合约 / 指数合约」行情，口径一致，可随时热切换。

加权算法金投网提供的持仓量加权官方按持仓量加权计算

分钟 K 上限500 根（接口硬上限）4000 根
日 K 回溯约 3.5 年（2023/08 起，新品种更晚）2016/01 起（10 年+）
首次连接耗时约 1 秒（缓存命中）约 18~35 秒（首连登录 + 订阅）
会话稳定性无状态 HTTP，无会话问题需维持连接，tqsdk 有单线程约束

全量遍历 hq-1 ~ hq-1500，取 symbolName 含「加权」的页面，共 88 个。

数据接口

用途接口关键字段
实时行情api.jijinhao.com 批量报价status（100 交易中 / 110、120 休市）、time（毫秒时间戳）
分时数据当日分时接口约 145 个点
分钟 K5 / 15 / 30 分钟接口单次上限 500 根（pageSize 参数无效）

⚠️ status 字段是本项目判断交易时段的第一优先级信号；time 字段配合「行情新鲜度」判断，可自动适配夜盘差异与节假日。

限速与并发

曲合接口对单 IP 有软限速。本项目用线程池并发拉取，并内置单站重试（失败隔 350ms 重试 1 次）； 88 个品种实时行情实测 0.5 秒完成。

3. 天勤 TqSdk

账号与登录

使用快期账号登录（在 ⚙️ 设置 → 数据源 填写）。登录成功后自动订阅全部品种的指数合约。

项实测值
指数合约写法KQ.i@<交易所>.<品种>，如 KQ.i@SHFE.cu
品种发现方式api.query_quotes(ins_class="FUTURE") 反推产品清单
订阅合约数174 个（主连 + 指数，按品种需求）
有效品种数87
K 线上限分钟 K 4000 根、日 K 3600 根
首连耗时18~35 秒

单线程约束与子线程 Actor

⚠️ tqsdk 有严格的单线程约束：所有 API 调用必须在同一线程内完成，跨线程直接调用会抛异常。 本项目在 天勤行情.py 里实现了一个 子线程 Actor + 任务队列 模型 —— HTTP 服务线程把请求投递到队列，由专职线程串行执行 tqsdk 调用并回传结果，从而在 Flask 式多线程服务中安全使用 tqsdk。

trading 字段的坑

tqsdk 返回的行情字典中没有可靠的「是否交易中」字段。早期实现里写死了 "trading": True， 会绕过邮件守护的交易时段门禁；现已改为 None，统一交由「行情数据新鲜度」判断。

4. 加权口径一致性

两个数据源虽然代码写法不同，但口径一致——均为持仓量加权：

加权价 = Σ(合约收盘价 × 该合约持仓量) / Σ(持仓量)
数据源加权合约加权算法来源
曲合网JO_xxxxxx 加权合约金投网直接提供「XX加权」
天勤KQ.i@交易所.品种 指数合约官方按持仓量加权计算
✅ 实测验证：同一品种在两天勤/曲合两侧的加权价走势一致（差值在最小变动价位内），切换数据源后 历史 H / L / M 会自动按新源重算，偏离度排名随之更新。

原因：这 5 个品种早已零成交、零持仓，实质停止交易。天勤仍按最后结算价维护一个报价（所以还能查到一个数字）， 曲合网（金投网）则已彻底停止对这些合约提供行情，所有接口都返回 0。

另有 晚籼稻 CZCE.LR：曲合有页面但同样无行情，天勤已无此产品 —— 两边都拿不到数据。
📌 因此看板在曲合源下显示 82 个品种、天勤源下显示 87 个品种，这是数据源的真实差异，不是程序缺陷。

10. 交易时段判定

用于「邮件只在交易时段发送」的门禁。优先级从高到低，任一条成立即视为「交易中」：

优先级依据说明
1交易所状态曲合返回的 status == 100 表示交易中
2行情数据新鲜度距最后一笔行情 ≤ mailStaleSec（默认 300 秒）
3交易所时段表内置 EXCH_SESSIONS 粗表，仅在前两条都取不到时兜底

为什么以「行情数据新鲜度」为主：行情时间戳天然就是最新交易时刻，闭市即冻结，因此可以零维护地自动适配：

  • 同一交易所内不同品种的夜盘差异（沪铜夜盘到 01:00、螺纹钢到 23:00）
  • 三大交易所夜盘规则的历次调整
  • 周末、法定节假日、临时休市
📌 实测（2026-10-13 00:00 周一）：沪铜 / 沪银 / 原油 → 开市；螺纹钢 / 铁矿石 / 纯碱 → 闭市（夜盘 23:00 已结束）； 碳酸锂 / 多晶硅 / 沪深300 → 闭市（无夜盘）。判定结果与实际完全一致。
